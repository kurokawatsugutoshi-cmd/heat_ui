## 1. 共通

### 1.1 何を作るか

作業員・職長・現場監督・本部がブラウザで使う熱中症対策のWebアプリ。朝の入場時と日中の定時に体調を記録し、基準超過と日中の異変で作業を止め、管理者が対応内容を残す。

### 1.2 利用者と見える範囲

設定画面に出す権限名を正とする。

| レベル | 画面上の名称 | 見える範囲 | 主な操作 |
| --- | --- | --- | --- |
| Level 1 | 本部 | 全現場横断 | 現場切替、設定（設問・閾値・権限・気象・休憩・表示列・一斉お知らせ）、CSV / PDF出力 |
| Level 2 | 現場監督 | 担当現場すべて | 担当現場の一覧、アラート対応 |
| Level 3 | 職長 | 自社作業員のみ | 自社の一覧、アラート対応、職長自身の定時チェック |
| — | 作業員 | 自分の画面のみ | 同意、朝チェック、定時チェック、危険時の休憩報告 |

職長は作業員と同じホームと定時チェックを持つ（A-01の下段）。旧領域仕様 D03 の「職長は体調を送れない」は採用しない。

### 1.3 顔認証と体調の分離

顔認証は本人と入場の確定だけに使う。体調・血圧・脈拍・睡眠の値は顔認証から受け取らない。

1. 既存の顔認証ゲートが入場を確定する。
2. 本システムは URL トークンで、作業員ID・氏名・所属会社・現場・入場時刻を受け取る。
3. 初回入場だけ W-01 で同意を取る。2日目以降は W-01 を出さず W-02 を開く。
4. 顔認証を通過していないトークンでは、エラー画面「入場ゲートを通過してから再度読み取ってください」を出す。健康データの入力欄は出さない。

相手システムの製品名、署名方式、トークンの寿命、未登録IDの扱いは未確定（本書 §11）。

### 1.4 言語

作業員・職長のスマホ画面のヘッダー右に `Globe` とプルダウンを置く。選択肢は `JP / VI / EN / ZH / ID`。表示例は `JP | 日本語`。

確定している本文は日本語である。他言語の全文辞書は未確定。管理画面（Admin）の多言語化は未確定で、現状の原稿は日本語のみ。絵文字は使わない。

```text

  ├ 未通過 → ゲート案内エラー
  ├ 初回 → W-01 → W-02
  └ 2日目以降 → W-02
W-02
  ├ 良い／普通 かつ 血圧 179/109 以下 → 「入場受付完了」→ W-04
  └ 体調「悪い」または 血圧 180/110 以上 → W-03

W-04 → W-04_2

A-01「対応画面を開く」→ A-02
A-02 未対応 → 向かう → 対応完了 → 処置4択 → 対応記録完了
Admin の行クリック → Drawer
Admin「設定」→ Settings
```

## 2. W-01 入場QR自動認証 ＆ 初回同意

### 目的

トークンで本人が確定したことを示し、健康データの取り扱いへの同意を初回だけ取る。

### 入口

顔認証通過済みの URL トークン。同意済みの人には出さない。

### 表示（確定文言）

ヘッダー左は会社名（14px・グレー）と氏名（16px・太字）。原稿の例は「〇〇工務店」「大和 太郎」。右は言語プルダウン。

本人照合枠（アイスブルー、左に青の 4px 線）:

- アイコン `ScanFace`
- 見出し: 顔認証ゲート通過データと照合完了
- 補足: 大和ハウス 〇〇新築工事現場（入場時刻 07:41）

同意カード（白、枠、角丸 8px）:

- 題: 健康データ・要配慮個人情報の取り扱いについて
- 本文:
  - 本システムは、熱中症予防および安全管理を目的として、体調・血圧・脈拍・睡眠時間等の健康データを取得します。
  - 取得したデータは、元請安全衛生管理者および所属会社の職長のみが閲覧し、安全管理の目的外には利用いたしません。
  - データは暗号化して保管し、工事終了後、法令に定める保管期間を経過した時点で破棄します。

主ボタン（高さ 48px）: 同意して朝のチェックへ進む

注釈（12px）: ※この同意画面は初回入場時のみ表示されます

### 操作

同意ボタンで同意日時・作業員ID・文面の版を保存し、W-02 へ進む。同意前の健康入力は受け付けない。

### 未確定

同意文の版管理、撤回操作の画面、保管年数の具体値、他言語の確定文面。

## 3. W-02 朝の体調・バイタルチェック

### 目的

入場前に、体調・血圧・脈拍・睡眠を1画面で記録する。

### 表示（確定文言）

題: 朝の体調チェック。サブ表記: 10/31 (土)（日付は当日）。

設問1 今日の体調。3択。初期選択は「良い」。

| 選択肢 | アイコン | 選択時 |
| --- | --- | --- |
| 良い | Smile | 青枠・アイスブルー背景 |
| 普通 | Meh | 琥珀枠・琥珀背景 |
| 悪い | Frown | 赤枠・赤背景 |

設問2 朝の血圧・脈拍（血圧計の数値を入力）。各行は `-10` と `+10`。

| 項目 | 初期値 | 単位 |
| --- | --- | --- |
| 最高血圧 | 120 | mmHg |
| 最低血圧 | 80 | mmHg |
| 脈拍 | 70 | bpm |

設問3 昨日の睡眠時間。初期選択は「7時間以上」。選択肢は「7時間以上」「6時間」「5時間以下」。

主ボタン: 入力完了（入場する）

### 判定（この画面の確定ルール）

| 条件 | 結果 |
| --- | --- |
| 体調が「良い」または「普通」、かつ最高血圧 179 以下、かつ最低血圧 109 以下 | トースト「入場受付完了」のあと W-04 |
| 体調が「悪い」、または最高血圧 180 以上、または最低血圧 110 以上 | W-03 をすぐ出す |

睡眠「5時間以下」だけでは入場を止めない。止まったときに、睡眠不足であれば W-03 の理由一覧へ載せる。

脈拍は記録する。入場ストップの条件には含めない。旧領域仕様 D09 の 160/100 や脈拍 120 は、この画面の入場判定には使わない。設定画面の初期閾値も最高 180・最低 110・睡眠 5時間以下とする。

### 保存する値

作業員ID、業務日、体調（良い／普通／悪い）、最高血圧、最低血圧、脈拍、睡眠（7時間以上／6時間／5時間以下）、送信日時、判定（入場可／入場ストップ）。

## 4. W-03 入場制限・上長確認モーダル

### 目的

基準を超えた人の作業開始を、職長または監督の対面確認まで止める。

### 表示（確定文言）

白モーダル。上辺だけ赤 4px。工事テープ模様は使わない。

- アイコン `AlertOctagon`、題: 入場ストップ（要・上長確認）
- 説明: 以下の項目が安全基準を超過しているため、作業開始前に職長または現場監督の対面確認を受けてください。
- 検知項目（赤の薄枠）。超えた項目だけを箇条書きにする。原稿例:
  - 朝の血圧：180 / 110 mmHg（基準超過）
  - 昨日の睡眠：5時間以下（睡眠不足）
  - 体調が「悪い」なら「今日の体調：悪い」
- 通知枠: 担当職長（鈴木 一郎）へ自動通知しました。詰所にて待機してください。
- ボタン（アイコン `UserCheck`、背景 `#0F172A`）: 上長確認済（面談後に押下で解除）
- 注釈: ※対面での状態確認後、職長または監督が操作してください

### 操作

画面を開いた時点で担当職長へ通知する。解除ボタンは職長または監督の操作として記録し、入場可にして W-04 へ進む。作業員本人の解除は想定しない。本人確認の強さ（職長の端末で押すのか、作業員端末を職長が操作するのか）は未確定。

## 5. W-04 作業員・職長 共通ホーム

### 目的

待機中に、休憩案内・現場気象・本日の進み具合を見せ、定時チェックと緊急連絡へ進ませる。

### 表示（確定文言）

題: お知らせ・気象情報

右バッジ: ● 作業中（緑の薄枠）

定時リマインド（アイスブルー枠、アイコン `Bell`）:

14:00 休憩時間です。水分を補給して定時チェックを行ってください。

管理画面の一斉お知らせがあるときは、この枠の下段に1行出す。最大120文字。

気象カード（白）:

- 現在の現場気象（大阪市北区）
- 右バッジ: WBGT 31.2℃｜厳重警戒（このバッジだけ赤の薄枠）
- 現在の気温 33.5℃
- 予測: アイコン `TrendingUp`。14時台にかけて 36.0℃ まで上昇予想（15分ごとの水分補給を推奨）

本日のサマリー（3枚）:

| 項目 | 例 |
| --- | --- |
| 本日の報告 | 4 / 6 回 |
| 次の定時休憩 | 15:00 |
| 朝の判定 | 良好、または 要注意 |

主ボタン（アイコン `CheckCircle2`）: 定時チェックへ進む → W-04_2

緊急ボタン（白地・赤枠・アイコン `PhoneCall`）: 緊急連絡（工事課員・救護直通）

気温カードをオレンジのグラデーションにしない。

### データ

気温・WBGT・地域は現場の現在地設定から取る。原稿の数値は表示例。気象の取得元APIは未確定。緊急連絡先の電話番号は現場設定として持つ（原稿の画面には番号を出さない）。

## 6. W-04_2 日中の定時チェック

### 目的

休憩のたびに、補給・体調・脱水の疑いを短く記録する。

### 表示（確定文言）

題: 定時チェック（14:00 休憩枠）。時刻は対象の休憩枠。

設問1 水分・塩分の補給（補給したらタップ、2列）:

| ボタン | アイコン | 押下時 |
| --- | --- | --- |
| 水分をとった | Droplets | 青背景・白文字、右上に Check |
| 塩分をとった | Pill | 同じ |

設問2 今の体調:

| 選択肢 | アイコン | 補足 |
| --- | --- | --- |
| 元気 | Smile | 変化なし |
| 少しだるい | Meh | バテ気味 |
| 異変あり | Frown | めまい・吐き気等 |

設問3 脱水セルフチェック（確認ガイド）。アイスブルー枠にアイコン `Hand` と次の文:

爪先を3秒押して赤みがすぐ戻るか、手の甲の皮膚をつまんで戻るか確認してください。

チェックは1つ: 戻りが遅い・脱水の疑いがある場合はチェック

主ボタン: 確認して送信する

緊急ボタン: 緊急連絡（工事課員へ直通）

### 判定

「異変あり」を選んで送信したら W-05 を開く。W-05 の検知文は「14:25 定時報告で『異変あり（めまい）』を検知」。

「元気」「少しだるい」の送信後の戻り先は W-04。脱水チェックだけでは W-05 にしない（その先の扱いは未確定）。

### 保存する値

作業員ID、休憩枠の日時、水分、塩分、体調3値、脱水疑いの有無、送信日時。

## 7. W-05 日中危険アラート（2段階）

### 目的

異変の申告で作業を止め、休憩開始と、その後の復帰か救護連絡を本人に選ばせる。

### 共通

この画面だけ背景を `#DC2626` にする。

- 題: 作業ストップ（危険アラート発令）
- サブバッジ: 14:25 定時報告で「異変あり（めまい）」を検知
- 中央は白カード

### State 1 発令直後

- 見出し（赤文字）: 直ちに作業を中断してください
- 手順:
  1. 作業を止め、近くの日陰・クールスポットへ移動する
  2. 衣服を緩め、首・脇の下・足の付け根を冷却する
  3. 水分・塩分を摂取し、横になって休む
- 主ボタン（白地・赤文字）: 水分を摂り、休憩に入りました
- 緊急ボタン（琥珀背景 `#FBBF24`、文字 `#020617`）: 緊急連絡（工事課員へ直通電話）

「水分を摂り、休憩に入りました」で State 2 に切り替える。カードの文とボタンの両方が変わる。

### State 2 休憩中

- バッジ: 休憩・経過観察中（上長へ通知済）
- 本文: ひとりで立ち上がれるようになり、めまいやだるさが完全に消えてから作業に戻ってください。少しでも不安がある場合は上長へ連絡してください。
- ボタンA（白地）: 体調が回復したため作業に復帰する
- ボタンB（琥珀）: 回復しないため上長・救護へ連絡する

State 2 に入ったとき、担当職長へ通知する。

### 未確定

復帰ボタンのあとどの画面へ戻すか、救護連絡の電話番号、通知の実チャネル（Teams かプッシュか）。画面原稿は State 2 のボタンまでである。

## 9. A-02 アラート対応 ＆ 処置内容4択

### 目的

誰が向かうかを全管理者で共有し、終わった処置を4択で残す。

### 対象者カード（確定文言）

- 〇〇鉄筋工業（一次請け）／ グエン・ヴァン（言語：JP / VI）
- 理由タグの例: 朝の血圧 180/110（基準超過）／ 睡眠 5時間以下／ 14:25 定時報告：めまい

理由は、その人の朝チェックと、今回の定時チェックから作る。

### State 1 未対応

- ヘッダー帯（赤）: アラート発生中（14:25 検知）
- バッジ: ● 未対応
- 主ボタン（アイコン `Navigation`）: 向かう（自分が対応する）
- 横並び: 本人へ電話（グレー枠）／ 救護本部へ連絡（赤枠・赤文字）

### State 2 対応中

「向かう」を押した人を対応者として全管理者へ同期する。

- ヘッダー帯: `#1E293B`（濃紺）

### State 3 処置4択

見出し: 処置結果の選択（労基署・監査ログ記録用）

2. 注意して作業継続（経過観察）（軽作業へ変更 ※翌日の要注意リストへ自動引継）
3. 本日の作業中止・早退（体調を考慮し、本日の作業を打ち切り帰宅指示）
4. 医療機関へ搬送（緊急）（現場監督・救護本部と連携し病院へ搬送）

1つ選ぶとバッジを「対応記録完了」（緑）にする。選んだ文言、対応者、日時を監査ログに残す。2を選んだ人は翌日の朝の要注意へ引き継ぐ。
