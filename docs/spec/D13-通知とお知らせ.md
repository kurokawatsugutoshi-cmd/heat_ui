## 1. 目的

誰に、いつ、何を知らせるかを定義する。

## 2. 適用範囲

定義すること: 警告、注意、入力の抜け、お知らせの宛先と経路。対応状態。

定義しないこと: 判定の式（D09）、画面の部品（D06 の A-04、W-11）、言語の欠けの規則の中身（D12）。

## 3. 参照

- `report-0924.pdf` の残課題（管理者へのリアルタイムアラート、利用者へのお知らせ）
- D03 の受信範囲

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| open | 未対応 |
| in_progress | 対応中 |
| done | 対応済 |
| お知らせ | 管理者が出す文章。判定とは別 |

## 5. 要求

| ID | 要求 | 状態 |
| --- | --- | --- |
| D13-R01 | 警告の回答は、現場の所長、その会社の職長、通知を有効にした本部に残る | 確定 |
| D13-R02 | 注意を即時に知らせるかは未決とする。未決の間は一覧の着色を先にする | 未決 |
| D13-R03 | 入力の抜けを作業者のプッシュで必須配送にしない。管理者の一覧を先にする | 仮 |
| D13-R04 | お知らせは対象現場と公開期間のあいだ、作業者にアプリ内で見える。訳が無い言語には出さない | 確定 |
| D13-R05 | メールの送信に失敗しても、回答と判定は残す。一次の情報は管理画面とする | 確定 |
| D13-R06 | メール本文に測定値を載せるかは未決とする | 未決 |

## 6. 仕様

| 事象 | 条件 | 宛先 | 経路 | 状態 |
| --- | --- | --- | --- | --- |
| 警告 | D09 の level が alert | 所長、該当職長、通知ONの本部 | メールと A-04 | 確定。チャットは Q.13.02 |
| 注意 | Q.13.01 が即時と言ったとき | 同上 | まず A-02 の着色 | 未決 |
| 入力の抜け | マスタ上の未出社、休憩間隔の超過 | 管理者 | A-04 | 作業者プッシュは Q.13.03 |
| お知らせ | 期間内の対象現場 | 作業者 | W-11。言語別本文 | 確定 |

対応状態は open、in_progress、done（D13-R01 の追跡）。

## 7. 他領域との受け渡し

受け取るもの: level（D09）、ロールの範囲（D03）、有効言語（D12）。

渡すもの: 対応状態。D06 の A-04 と W-11 が表示する。

## 8. 未決事項

| ID | 問い | 理由 |
| --- | --- | --- |
| Q.13.01 | 黄を即時に知らせるか | 資料は赤の通知が残課題。黄は一覧の色として始まる |
| Q.13.02 | Teams などのチャット連携をするか | 連携先が未指定 |
| Q.13.03 | 作業者へのプッシュを必須にするか | Web では到達が不安定。今回は必須外の仮 |
| Q.13.04 | メールに測定値を載せるか | 転送による漏えい |
