## 1. 目的

機能以外の最低限と、完成とみなす確認を定義する。

## 2. 適用範囲

定義すること: 利用環境、操作量、通信、個人情報の扱いの方針、受入の確認項目。

定義しないこと: 各機能の規則（D03〜D16）、保管期間の年数（D14 の Q.14.01）。

## 3. 参照

- D01 の目的
- D02 の今回の範囲

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| 受入 | その確認がすべてできて、今回の範囲を満たしたとみなす項目 |

## 5. 要求

| ID | 要求 | 状態 |
| --- | --- | --- |
| D17-R01 | 作業者は近い世代の iOS Safari と Android Chrome、管理者はデスクトップの Chrome、Edge、Safari で操作できる | 仮 |
| D17-R02 | 休憩時の設問数は、本人確定のあと D07 の休憩設問と送信を超えて増やさない | 確定 |
| D17-R03 | 屋外と手袋を想定し、選択肢の操作領域を大きくする | 確定 |
| D17-R04 | 通信は TLS とする。管理の入口は認証が必要である。送信の入口は現場トークンを検証する | 確定 |
| D17-R05 | 氏名、会社、血圧、脈拍、自覚症状は健康情報であり、目的の外に使わない | 確定 |
| D17-R06 | 本システムは診断をしない。測定と救護は現場の手順に従う | 確定 |
| D17-R07 | 受入は第6章の10項目とする | 確定 |

## 6. 仕様

補足（D17-R01、D17-R05、D17-R06）:

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| バックアップ | 日次。戻す手順はインフラの別紙 | 仮 |
| ログ | 現場トークンを問い合わせ文字の生の値のまま残し続けない | 確定 |
| 免責の文面 | 画面に出す文は未決 | 未決 |

受入（D17-R07）:

| ID | 確認 |
| --- | --- |
| D17-A01 | 標準カメラの現場QRから、インストールなしで出社または休憩の画面が開く |
| D17-A02 | 出社時の属性と出社時の設問が、D08 の別スロットに入り、一覧に D09 の表示で出る |
| D17-A03 | 休憩時は補給と体調の設問だけで送れ、測定値のスロットが作られない |
| D17-A04 | 警告の回答で、権限のある管理者に通知が残り、一覧が警告になる |
| D17-A05 | 職長は自社の外を見られない。所長は他現場を見られない |
| D17-A06 | 言語を変えると、設問、ボタン、応急処置、エラーが選択した言語になる |
| D17-A07 | 個人QRでは本人の画面に氏名と会社が入り、その画面に設問が無い |
| D17-A08 | 手入力を許す現場では、個人トークンが無くても現場QRから記録できる |
| D17-A09 | 応急処置と電話は、送信の前後どちらでも開ける |
| D17-A10 | 共有端末で終了したあと、次の人が前任者の氏名のまま送れない |

## 7. 他領域との受け渡し

受入の各行は、D05、D06、D07、D08、D09、D03、D12、D11、D10 の要求が通ったことの確認である。新しい受入を足すときは、先に対応する領域の要求を置く。
