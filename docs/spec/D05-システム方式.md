## 1. 目的

本システムを Web としてどの構成で置くかを定義する。

## 2. 適用範囲

定義すること: 利用者の端末、サーバの役割、QRの読み取り方、オフラインの扱いの方針。

定義しないこと: URLの形（D15）、トークンの意味（D10）、判定の式（D09）。

## 3. 参照

- D02-R01
- `spec-heatstroke-app.pdf` の利用環境

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| 作業者Web | スマホ幅を主とするブラウザ画面 |
| 管理コンソール | PC幅を主とするブラウザ画面 |
| PWA | ホーム画面への追加。今回は任意 |

## 5. 要求

| ID | 要求 | 状態 |
| --- | --- | --- |
| D05-R01 | 作業者と管理者はブラウザから HTTPS で利用する | 確定 |
| D05-R02 | 作業者画面はスマホ幅、管理者画面はPC幅を主とし、共有タブレットでも操作できる | 確定 |
| D05-R03 | QRは端末の標準カメラで読む。アプリ内カメラを必須にしない | 確定 |
| D05-R04 | 回答の保存と同時に判定を実行する | 確定 |
| D05-R05 | プッシュ通知を届ける前提で PWA を必須にしない | 確定 |
| D05-R06 | オフラインでの蓄積は今回の必須にしない。送信に失敗した入力は未送信のまま残す | 仮 |

## 6. 仕様

```
作業者のブラウザ --HTTPS--> 作業者Web
管理者のブラウザ --HTTPS--> 管理コンソール
                               API（認証、保存、判定、通知）
                               データベース
                               メール
                               既存の顔認証（接続の中身は D11）
```

D05-R06 の送信失敗時の画面上の扱いは D16 の E-12 に従う。オフライン蓄積を将来の必須にするかは未決である。

## 7. 他領域との受け渡し

構成図の各箱は、認証（D10）、保存する値（D08）、判定（D09）、通知（D13）、外部の形（D15）が中身を定義する。

## 8. 未決事項

| ID | 問い | 理由 |
| --- | --- | --- |
| Q.05.01 | 作業者向けのオフライン蓄積を将来の必須にするか | 現場の電波条件が資料に無い。今回は必須外の仮 |
