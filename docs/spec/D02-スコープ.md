## 1. 目的

今回の対象、設計だけ残すもの、対象外を分ける。

## 2. 適用範囲

定義すること: 提供形態と、含める範囲・含めない範囲。

定義しないこと: 各機能の中身（D03〜D17）、目的そのもの（D01）。

## 3. 参照

- D01
- `spec-heatstroke-app.pdf`（Webアプリとする方針、ネイティブとの比較は検討メモ）

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| 今回 | 利用者が使える範囲として仕様を閉じるもの |
| 設計のみ | 条件が揃うまで利用機能にしない。仕様の置き場所だけ持つ |
| 対象外 | 今回の仕様に機能として書かないもの |

## 5. 要求

| ID | 要求 | 状態 |
| --- | --- | --- |
| D02-R01 | 提供形態は Webアプリとする | 確定 |
| D02-R02 | 今回は、作業者の入力と閲覧、管理者の一覧と権限制御、黄と赤、赤の通知、辞書による多言語、現場QRを対象とする | 確定 |
| D02-R03 | 既存の顔認証との連携は設計のみとし、常時のAPI接続は接続条件が揃うまで対象の機能にしない | 確定 |
| D02-R04 | 新規入場者教育など他の安全衛生チェックは、今回の画面を作らない | 確定 |
| D02-R05 | ストア向けのネイティブアプリ、本アプリのカメラによる顔照合、表情からの体調推定、血圧計からの自動取込、ブラウザ翻訳への誘導、240言語の同時提供は対象外とする | 確定 |

## 6. 仕様

| 区分 | 内容 | 続きを書く領域 |
| --- | --- | --- |
| 今回 | 作業者Web、管理者Web、判定、赤の通知、辞書の多言語、現場QR | D05〜D17 |
| 設計のみ | 既存顔認証との連携。第一候補は個人QRまたは一時URL | D11 |
| 将来 | 新規入場者教育、他のチェック。現場・会社・作業者の識別子は流用できる形だけ残す | D14 |
| 対象外 | D02-R05 の列挙 | D11、D12 |

## 7. 他領域との受け渡し

対象外にした機能は、該当領域の「定義しないこと」にも同じ境界を書く。新しい対象を足すときは、先にこの文書の表を更新する。
