# 仕様書の最低限の項目

領域 D01〜D18 の各文書は、このページの項目を欠けずに持つ。中身が少なくても見出しは残す。該当が無いときは「なし」と書く。

| 項目 | 内容 |
| --- | --- |
| 文書番号 | HS-SPEC-00 |
| 文書名 | 仕様書の構成 |
| 版 | 0.1 |
| 状態 | ドラフト |
| 日付 | 2026-10-01 |

## 1. この文書の目的

D01〜D18 を仕様書として書くときの必須項目を固定する。話題の定義そのものは各領域の文書にある。

## 2. 適用範囲

各領域ファイル `docs/spec/Dxx-*.md` に適用する。画面のプログラム、データベースの実体、`web/` には適用しない。

## 3. 必須項目

領域文書は、次の順で見出しを置く。

| 順 | 見出し | 書くこと |
| --- | --- | --- |
| 表紙 | 文書情報 | 文書番号、文書名、版、状態、日付。状態は ドラフト / レビュー / 確定 |
| 1 | 目的 | この領域が決める問いを1つ |
| 2 | 適用範囲 | 「定義すること」と「定義しないこと」。定義しない先は Dxx を指す |
| 3 | 参照 | 元資料、関連する領域文書。引用が無ければ「なし」 |
| 4 | 用語 | この領域で意味を固定する語。無ければ「なし」 |
| 5 | 要求 | 番号、文章、状態。1文は検証できる内容にする。状態は 確定 / 仮 / 未決 |
| 6 | 仕様 | 要求を具体化した表・規則・一覧。要求番号を添える |
| 7 | 他領域との受け渡し | 渡す識別子、受け取る識別子 |
| 8 | 未決事項 | 疑問ID、問い、決められない理由。無ければ「なし」 |
| 9 | 改訂履歴 | 版、日付、内容 |

要求の番号は `Dxx-R01` から連番にする。疑問の番号は `Q.xx.01` から連番にし、D18 に同じIDで写す。

## 4. 書くときの規則

- 1つの事実の定義先は1つの領域だけにする。
- 仮の数値や仮の文言を、状態「確定」にしない。
- 未決を閉じたように書かない。仮の採用は仕様の中で「仮」と書き、未決のIDを残す。
- 新しい画面、設問、値種別は、発行する領域に行を足してから他領域が参照する。画面は D06、設問は D07、値種別は D08。
