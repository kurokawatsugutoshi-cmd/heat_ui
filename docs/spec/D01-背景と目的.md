## 1. 目的

このシステムが解決する課題と、達成したい結果を定義する。

## 2. 適用範囲

定義すること: 課題の出どころ、紙と現行フォームと本システムの違い、目的。

定義しないこと: 作る機能の境界（D02）、人の手順（D04）、画面（D06）。

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| 紙の確認表 | 「水分・塩分・体調 確認表」。1時間ごとに現場内へ移動して手記入する運用 |

| 本システム | 現行のチェックを置き換える Webアプリ |

## 5. 要求

| ID | 要求 | 状態 |
| --- | --- | --- |
| D01-R01 | 本システムの目的は、休憩時の報告を休憩所などで1分未満に収めることである | 確定 |
| D01-R02 | 紙の確認表をやめ、記録は即時に集計できること | 確定 |
| D01-R03 | 不調の見落としを減らし、応急処置の周知と緊急連絡を含めて重症化を抑えること | 確定 |

## 6. 仕様

令和7年6月1日から、職場の熱中症対策は改正労働安全衛生規則で強化されている。改善事例の現場は、紙の確認表を1時間ごとに移動して記入していた。

| 時点 | 記録 | 残ること |
| --- | --- | --- |
| 紙 | 往復約6分。1現場あたり年間約1,600枚。集計約30分/日 | チェックが形骸化し、初期症状の共有が遅れる |
| 現行 | 現場QRから入力。黄と赤の色分け。ブラウザ翻訳 | 管理者への自動通知、権限の分離、アプリ内の多言語、顔認証との本人の紐づけが無い |
| 本システム | 現行のチェックを Webアプリとして持つ | 機能の境界は D02 |

目的は D01-R01 から D01-R03 の3つである。

## 7. 他領域との受け渡し

D02 へ「本システムの目的」を渡す。機能一覧はこの文書では作らない。
