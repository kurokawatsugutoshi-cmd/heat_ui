## 1. 目的

作業者と管理者の作業を、時間の順に定義する。

## 2. 適用範囲

定義すること: 前日、出社時、作業中、緊急時に人が行うこと。

定義しないこと: 画面の部品（D06）、設問の文言（D07）、判定式（D09）。

## 3. 参照

- `report-0924.pdf` の対策と効果
- `proposal-heatstroke-app.pdf` の作業者と管理者の対比

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| 出社時 | 作業前に1回行う体調の記録 |
| 休憩時 | 作業中、目安1時間ごとに行う補給と体調の報告 |
| 業務日 | 記録を「その日」に束ねる日付。区切り時刻は D16 の Q.16.01 |

## 5. 要求

| ID | 要求 | 状態 |
| --- | --- | --- |
| D04-R01 | 前日、管理者は出社用と休憩用のQRを休憩所などに置く | 確定 |
| D04-R02 | 出社時、作業者は血圧と脈拍を人が測定し、出社用QRから本人を確定したあと設問へ答える | 確定 |
| D04-R03 | 出社時の送信のあと、判定と、条件を満たす通知が行われる | 確定 |
| D04-R04 | 作業中、作業者は休憩所で休憩用QRから休憩時の設問を送る | 確定 |
| D04-R05 | 緊急時、人は応急処置の内容を見て現場の直通へ電話する。救護の判断は人の作業とする | 確定 |

## 6. 仕様

前日: 作業者の睡眠などは自己管理である。アプリへ入るのは翌朝の睡眠区分（D07 の `Q-SLEEP`）としてである。管理者は2種類のQRを置く（D04-R01）。

出社時: 測定、出社用QR、本人の確定（D10、D11）、出社時の設問（D07）。保存と同時に D09 が判定し、D13 が通知条件を見る（D04-R02、D04-R03）。

作業中: 目安1時間ごとに休憩時の設問を送る（D04-R04）。

緊急時: 周知コンテンツ `C-AID` を見て電話する（D04-R05）。アプリは連絡と記録を持つ。

## 7. 他領域との受け渡し

手順の各手は、画面ID（D06）、設問コード（D07）、判定（D09）、通知（D13）を参照する。この文書は手順の順番だけを持つ。

## 8. 未決事項

なし。夜勤の日付の切り方は Q.16.01（D16）にある。
