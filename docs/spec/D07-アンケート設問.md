## 1. 目的

何を聞くか、選択肢の意味、回答を持たない周知を定義する。

## 2. 適用範囲

定義すること: フォーム種別、設問コード、仮の聞き方、必須、極性、悪い側の重さ、表示順、周知コンテンツ。

定義しないこと: 値の型と受理範囲（D08）、画面部品（D06）、黄赤の式（D09）。現場・会社・氏名は設問にしない（D10、D14）。顔写真と入場の成否は設問にしない（D11）。

## 3. 参照

- `report-0924.pdf` の集計シートの列と、入力画面のイラスト
- `spec-heatstroke-app.pdf` の出社時・休憩時の項目

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| arrival | 出社時体調チェック |
| break | 休憩時報告 |
| positive | 「はい」が良好 |
| negative | 「はい」が異常 |
| 周知コンテンツ | 読むだけで、回答の行を作らない情報。IDは `C-*` |

### 6.3 設問が持つ属性

`code`、`form_type`、言語ごとの `text`、`polarity`（はい／いいえのみ）、`severity_if_bad`（`none` / `caution` / `alert`。はい／いいえのみ）、`required`、`sort`、`active`、`value_kind`（D08 から選ぶ）。

公開は `active` かつ、有効な全言語に文があること（D12）。

## 7. 他領域との受け渡し

渡すもの: `code`、`form_type`、極性、悪い側の重さ、sort、`C-*`。

受け取ること: 値種別（D08）。画面は D06 が code を並べる。

## 8. 未決事項

| ID | 問い | 理由 |
| --- | --- | --- |
| Q.07.01 | 設問原文と、「はい」が良好か異常か | 縮小図から文が確定できない |
| Q.07.02 | 睡眠に「5時間未満」を含めるか | 資料の例は7時間以上、6時間、5時間 |
| Q.07.03 | 自由記述を足すか | 足す場合は先に D08 へ値種別を追加する |
| Q.07.04 | 今の体調は二値か段階か | 段階なら設問の値種別を作り直す |
| Q.07.05 | 休憩時に血圧を含めるか | 現行の休憩は補給と体調の簡易報告 |
| Q.07.06 | 応急処置の原文 | 図から全文を取れない |
| Q.07.07 | 仕事前チェックの本数と各列の原文 | 列数は仮に4 |
